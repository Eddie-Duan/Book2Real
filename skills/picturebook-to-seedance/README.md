# 绘本页转 Seedance 首帧 Skill

> **定位**：将绘本单页图像加工为适用于 Seedance 图生视频的首帧素材，并以可量化的方式验收加工结果。

---

## 0. 文档说明

本文件面向使用者，说明该 skill 的用途、适用范围与运行前提。执行规范以 `SKILL.md` 为准。本文件不包含流程指令，以避免与执行文档产生歧义。

---

## 1. 功能定位

| 项目 | 说明 |
|---|---|
| 输入 | 绘本单页图像，包含正文文字、艺术字标题、页码、水印及画中文字 |
| 输出 | 零文字首帧、结构化处理清单、量化质检报告、图生视频提示词 |
| 核心特征 | 画幅锁定、掩膜外像素级保真、批量可验收 |

---

## 2. 所解决的问题

### 2.1 原始页面直接输入时的失效模式

图生视频模型不区分文本内容与图像内容，会将文字识别为画面实体，导致文字随镜头运动产生拉伸、模糊与形变。此外，文字区域信息密度显著高于画面其他区域，易诱导模型对整页重新生成，造成画风与轮廓偏离。

因此，「首帧不含文字」属于输入有效性的前提条件，而非画质偏好。

### 2.2 手工去字的效率与验收缺陷

艺术字以及叠加于插画纹理之上的文字，在手工擦除后普遍残留边缘残影或填充斑块。更为关键的是，「未编辑区域是否保持原样」缺乏客观判据，仅能依赖人工目视确认。

本 skill 将该环节固化为脚本流程：修复仅作用于掩膜区域，掩膜外像素与原图逐位一致，并以 SSIM ≥ 0.9995、像素差分布、保护带入侵面积等指标给出量化判定。对于批量页面，可据此快速定位不合格样本。

### 2.3 去字导致的信息缺失

文字承担叙事信息，去除后画面信息量下降。典型情形：原文描述「三只蓝鸟俯冲至三叶草丛」，而原画仅在天空留白、未绘制鸟群；此时直接生成视频将得到静态主体镜头。

依据原文补全缺失的视觉内容，是该流程的核心价值，同时也是技术风险最高的环节。该环节须同时满足两项约束：补全内容可溯源至原文片段，补全区域不得侵入已有主体。

## 3. 交付物

单页输入对应以下四项产物：

| 文件 | 说明 |
|---|---|
| `clean_keyframe.png` | 零文字首帧，分辨率与宽高比与原图完全一致 |
| `page_manifest.json` | 文字块清单、去字掩膜位置、补全项目及其原文依据 |
| `qa_report.json` | 验收判据：尺寸偏差、SSIM、像素差分布、保护带入侵 |
| `seedance_prompt.txt` | 镜头运动、主体微动作、环境动态与负向约束 |

---

## 4. 适用范围

| 适用场景 | 不适用场景 |
|---|---|
| 绘本批量转制为短视频，页面数量在数十至数百量级 | 单页临时效果制作 |
| 验收要求为「除文字去除外，画面不作任何改动」 | 无保真要求的一般性编辑 |
| 需要反复迭代并保留版本可追溯记录 | 一次性交付、不留档 |
| 多人协作制作同一套书，需统一风格与处理口径 | 单人非正式修图 |

**结论**：单页或零星页面的临时处理，人工编辑成本更低。批量生产且需留存可核验记录时，本流程的价值主要体现于验收环节，而非编辑环节。

## 5. 运行前提

### 5.1 硬件与模型

完整保真路径依赖本地推理环境：SAM2、LaMa、Flux.1 Fill、Grounded-SAM、Depth Anything V2、Surya OCR，建议显存不低于 16 GB，磁盘预留约 60 GB。

### 5.2 自动化边界

本流程为多阶段流水线，非单步自动化工具。其中文字识别、原文与画面的差异分析、补全描述撰写等环节仍需人工判断与确认，不建议在无人值守条件下批量执行。

### 5.3 已知限制

1. **画中字处理存在内容损失**：按现有约束，招牌、书名等画面内文字一并清除，修复后仅补非可读笔触，原有文字信息不可恢复。该项待确认。
2. **质检阈值为初始值**：0.9995、0.25、25 px 等参数为经验初值，需以目标绘本的 10 页样本校准后使用。
3. **艺术字掩膜依赖人工兜底**：渐变字、镂空字、描边字的掩膜生成仍可能存在偏差，需人工复核。

### 5.4 降级路径

无 GPU 环境下可退化为云端图像编辑模型方案，此时输出图像将经过整图重编码，非编辑区域无法保证逐像素一致，SSIM 判据需相应放宽。具体方案见 `references/environment.md`。

---

## 6. 快速开始

1. **部署**：将整个目录放入 skills 目录，或直接提供给支持 `SKILL.md` 的 agent 使用。
2. **输入要求**：绘本扫描图，短边不低于 1024 px，单页构图。
3. **执行入口**：自 `SKILL.md` 的 Stage 0 起依次执行各阶段。
