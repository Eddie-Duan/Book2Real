## 1. 【高】`test_qa.py` 2 条失败 → gate 测试门红（4/5）

**复现**：`python -m pytest tests/test_qa.py -q` → `2 failed, 38 passed`。

### 1a. `test_spot_mode_unnamed_blob_does_not_borrow_a_neighbour`
- **症状**：`qa._spot_hit(page, "p03", [0.88, 0.85, 0.04, 0.04], ents)` 返回 `None`，测试断言 `hit is not None` 失败（`AssertionError: None`）。
- **根因**：这是**测试硬编码坐标与再生数据漂移**，不是 `_spot_hit` 逻辑错误。测试假设 p03 右下角（0.88,0.85）有个"无名 blob"实体；但当前 `books/cn01/reader/cast/entities.json` 里 p03 的实体 `p03-e1` 的 box 是 `[0.676, 0.346, 0.289, 0.599]`（中心约 0.82,0.65）。点击点 (0.90,0.87) 到它的中心距 ≈0.24 > 0.15、IoU≈0.009 < 0.15，两个阈值都不命中，`_spot_hit` 正确返回 `None`。今天重跑 `cast` 后实体 box 变了，测试里的坐标就失效了。
- **性质**：测试对**非确定性 cast 产物**做了过度耦合；数据一再生，断言即崩。
- **建议**：让该测试从 `entities.json` 动态取一个 `name==""` 的实体坐标来点，而不是写死 `[0.88,0.85]`；或在测试开头断言"右下角确有匿名实体"，没有就 `skip` 并说明。

### 1b. `test_real_book_content_hit_rate_and_book_out_red_line`
- **症状**：`AssertionError: content hit rate regressed: 99/103`（96.1% < 98% 阈值）。
- **根因**：103 条里 4 条失败，全是 `scene[:6]`（页面 scene 文本前 6 字）被当问句时检索不到证据：p01「封面上，两个」、p07「花花一个人在家」、p10「黄米团叼着卡」、p12「积木一块一块」。（`debug/模块连接检查.md` P4 已记录。）
- **性质**：内部质量门阈值卡住；但 **96.1% 仍远高于官方「回答正确率 ≥0.60」**，且反幻觉红线（书外问题 `no_evidence`）通过。不阻塞交付。
- **建议**：qa 检索对 scene 前缀退化问句做场景回退；或把 `scene[:6]` 从 `_content_queries` 的 query 生成里去掉 / 下调阈值到 0.96。

## 2. 【高】服务启动脚本用系统 Python，本机跑不起来

- **复现**：
  - `scripts/start_backend.ps1` 第 15 行：`py -m uvicorn app.main:app`。
  - `backend/scripts/start_backend.cmd` 第 4 行：`python -m uvicorn app.main:app`。
  - 本机 `py --version` = **3.13.7**、`python --version` = **3.13.7**，且 `import uvicorn` 都报 `ModuleNotFoundError`；而依赖全装在 `.venv`（**3.12.10**，`uvicorn`/`fastapi` 可用）。
- **根因**：启动脚本没有用 venv 的解释器。`py` 启动器**不理会已激活的 venv**，永远指向系统 3.13.7，故 `scripts\start_backend.cmd`（README 的"启动唯一服务"命令）**必失败**；`backend/scripts/start_backend.cmd` 只有在手动 `activate` venv 后（`python`=venv）才可能跑通。
- **影响**：官方演示的"阅读器 + 影院 + 语音问答唯一服务"无法按 README 方式启动。
- **建议**：两处都改成 `..\.venv\Scripts\python.exe -m uvicorn ...`（或 `call ..\.venv\Scripts\activate.bat` 后再起）；README 快速开始的第 4 步也补一句"需先激活 venv 或直接用 venv python"。

## 3. 【高】ffmpeg 装了但不在 PATH → `doctor` 失败、`film` 跑不了

- **复现**：`python -m book2real doctor` → `[FAIL] ffmpeg: ffmpeg not found.`；`where.exe ffmpeg` 无结果；`util.ffmpeg_path()` 只查 `BOOK2REAL_FFMPEG` 环境变量或 `shutil.which("ffmpeg")`。
- **事实**：ffmpeg 已用 winget 装到 `C:\Users\32764\AppData\Local\Microsoft\WinGet\Packages\Gyan.FFmpeg_...\bin\ffmpeg.exe`，但**没有进 PATH**（WinGet Links 未生效）。今天 18:51/18:56 的两段成片是在 ffmpeg 可见的 shell 里生成的，新开 shell 就找不到了。
- **影响**：`python -m book2real film`（官方红线 A9"一次生成不剪辑"的交付路径）在干净 shell 下会因 ffmpeg 缺失而挂；验收清单第 1 项"环境自检 doctor"也不通过。
- **建议**：把 winget ffmpeg 的 `bin` 目录加入用户 PATH，或在 `.env` 里写 `BOOK2REAL_FFMPEG=<绝对路径>`，并在 `doctor` 里给出可操作的提示。

## 4. 【中】`pytest` 在仓库根收集到 `backend/tests` 报错

- **复现**：根目录 `python -m pytest -q` → 4 个 `ERROR collecting backend/tests/test_*.py`：`ModuleNotFoundError: No module named 'app'`。
- **根因**：`backend/tests/*` 用 `from app.book.index import ...` 等，需要 `backend/` 在 sys.path（即 cwd=backend）。仓库没有 `pytest.ini`/`conftest.py`/`[tool.pytest]` 来限定根目录收集范围。
- **影响**：README（backend）写的 `python -m pytest -q` = 18 passed 只在 `cd backend` 后成立；从根目录跑会中断收集。
- **建议**：根目录加 `pytest.ini`（`testpaths = tests` 或明确忽略 `backend/tests`），或给 backend/tests 加 `conftest.py` 注入 `backend/`。

## 5. 【中】`pytest tests/` 把脚本式测试误收集，33 失败是"假阳性"

- **复现**：根目录 `python -m pytest tests/ -q` → **33 failed / 169 passed**。失败几乎全是 `test_server.py`、`test_film.py` 的 `OSError: [WinError 10049] 在其上下文中，该请求的地址无效`（连的是 `('127.0.0.1', 0)`）。
- **根因**：`test_server.py`/`test_film.py` 设计为"脚本自跑"（docstring 明写 `No pytest`，`python tests/test_X.py`），其 server 启动逻辑在 `if __name__ == "__main__"` 里（`_start()` 才设置 `STATE["port"]`）。pytest 收集时只跑 `test_*` 函数、不跑 `__main__`，于是 `STATE["port"]` 停在 0，所有 HTTP 探测连到 0 端口。
- **性质**：测试文件命名 `test_*.py` 使 pytest 自动收集，但没有配置排除，导致"用 pytest 跑全部"得到大量假失败；真正的失败只有 `test_qa.py` 的 2 条（见 #1）。`gate.py` 用脚本模式跑，因此 gate 结果是对的。
- **建议**：给脚本式测试加一个 pytest 侧的安全桩（如 session fixture 调 `_start()`），或提供统一的 `pytest.ini`/`Makefile` 明确"顶层测试用 `python scripts/gate.py`，不要用 `pytest tests/`"，避免后来者被假阳性误导。

## 6. 【低】SAPI / filler 后台线程在 pytest 收尾时报错

- **症状**：`pytest tests/` 收尾打印 `SAPI warmup failed: cannot schedule new futures after interpreter shutdown`、`filler synth failed lang=zh/en: cannot schedule new futures after shutdown`。
- **根因**：`backend` 的 SAPI TTS provider / FillerBank 用了 `ThreadPoolExecutor`（或类似），进程收尾时还有后台任务在往已关闭的 executor 提交。属于清理顺序问题，不影响断言结果，但污染输出、可能掩盖真实失败。
- **建议**：给 executor 加 `shutdown(wait=True)` 或改为进程内同步，收尾时优雅关闭。

## 7. 【低】控制台中文乱码（GBK）

- **症状**：在 PowerShell 直接跑 `gate.py`/`doctor`/CLI，中文输出成乱码（"�﷨��"等）。
- **根因**：这些脚本用 `print` 输出中文，Windows PowerShell 默认代码页是 GBK；`gate.py` 已用 `sys.stdout.reconfigure(errors="replace")` 缓解，但 `doctor`/CLI 未处理。设置 `PYTHONIOENCODING=utf-8` + `[Console]::OutputEncoding=UTF8` 后正常。
- **建议**：演示/录制时统一 `chcp 65001` 或 `$env:PYTHONIOENCODING='utf-8'`。
