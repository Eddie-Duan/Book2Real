## 二、问题清单

### P1 · rapidocr_onnxruntime 与 Python 3.13/3.14 不兼容【已解决】

- **症状**：`pip install rapidocr_onnxruntime>=1.3` 失败，报「找不到匹配版本」。
- **根因**：`rapidocr_onnxruntime` 最新版（1.4.4）要求 `Requires-Python <3.13`，本机只有 3.13（Program Files）和 3.14（MSYS2），都不满足。
- **影响**：OCR 依赖装不上 → 英文扫描页（en01-03）无法识别。
- **处理**：`winget install Python.Python.3.12 --scope user`，用 3.12 重建 venv，`rapidocr_onnxruntime-1.4.4` 正常安装。
- **建议**：`requirements.txt` 未声明 Python 上限，README 只写 `>=3.10`，容易误导；建议在 README 注明「OCR 依赖需 Python ≤3.12」，或迁移到新版 `rapidocr`（支持 3.13+）。

### P2 · 融合流程漏了 `import-pdf`（页图衔接断裂）【已解决，代码未改】

- **错误类型**：`FileNotFoundError`（运行时异常，`[Errno 2] No such file or directory`）。**不是变量类型错配**——所有变量类型（`Path`/`str`/`ndarray`）都正确，问题是「本应存在的文件不存在」。

- **是否属于项目本体错误**：**属于项目集成层缺陷**（融合不完整 + 文档缺步骤），**不属于**单模块代码逻辑错误，也**不是**类型错配。
  - `storybook.build()` 与 `backend_bridge.py` 各自内部逻辑都自洽、正确；
  - 但融合时承诺「阅读器包由 backend 入库结果重建」，桥却没有把**页图**桥过来，且 README 快速开始漏了生成页图的步骤。

- **完整报错链（traceback）**：
  ```

      w0, h0 = imread(src).shape[1], imread(src).shape[0]      # ← 报错点
  ```

- **关键代码定位**：
  | 文件（完整路径） | 行 | 内容 | 角色 |

  | `D:\AI+\Book2Real\book2real\storybook.py` | **566** | `src = book_dir / "pages" / pg["file"]` | 根因：拼出 `books/<id>/pages/pXX.jpg` 这个无人生成的路径 |

### P6 · Seedance 模型版本不一致【已解决】

  `doubao-seedance-2-5-260628` / `doubao-seedance-2-5-flash-261115` 不一致。
- **处理**：`.env` 改为 `doubao-seedance-2-5-flash-261115`（flash 更快更省），`cloud --check` 显示 ready，真实调用成功。

### P7 · 素材 zip 中文文件名乱码【已解决】

- **症状**：`纸书智伴企业预选赛绘本素材.zip` 是 macOS 打包（含 `__MACOSX`），中文文件名未设 UTF-8 标志，直接解压得到乱码目录名。
- **根因**：zip 内部以 UTF-8 字节存储但未置 bit-11，Python 按 CP437 解码成 mojibake。
- **处理**：解压时对非 ASCII 名做 `name.encode('cp437').decode('utf-8')` 还原。
- **注意**：解压后真实顶层目录名是 `企业预选赛绘本素材`（不是 README 写的 `纸书智伴企业预选赛绘本素材`）。

### P8 · `.env` 编码易被 PowerShell 破坏【提醒】

- **症状**：用 PowerShell `Set-Content` 改 `.env` 后，`cloud.py` 报 `UnicodeDecodeError: utf-8 codec can't decode ...`。
- **根因**：PowerShell 5.1 的 `Set-Content` 默认按系统 ANSI（GBK）写文件，而 `cloud.py` 用 `read_text(encoding="utf-8")` 读。
- **处理**：改用 Python `Path.write_text(..., encoding="utf-8")` 写 `.env`。
- **建议**：团队在 Windows 上改 `.env` 时用 UTF-8 编码编辑器；或给 `cloud.load_env()` 加 `errors="replace"` 容错。
