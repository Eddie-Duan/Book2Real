## 0. 问题根因（一句话）

`requirements.txt` 里的 `rapidocr_onnxruntime` **不支持 Python 3.13**；而本机 `py`/`python` 默认指向 3.13，且依赖全装在 `.venv`（3.12）。所有建环境/启动脚本却都在用 `py`/`python`，于是：建环境会失败（rapidocr 装不上）、启动会失败（无 uvicorn）。

**统一原则**：脚本里要么用 `py -3.12`（建 venv 时），要么用 `.venv\Scripts\python.exe`（建好 venv 之后）；绝不裸用 `py`/`python`。

## 1. 建环境脚本

### 1.1 `scripts/setup_env.ps1`
| 行 | 现状 | 改为 |
|---|---|---|
| 11 | `$py = "python"` | 探测 Python 3.10/3.11/3.12（用 `py -3.12` 等），找不到就报错并提示原因 |
| 15 | `& $py -m venv .venv` | 用上面探测到的 `$py` 建 venv（保持原样逻辑即可） |

建议改法（示意）：
```powershell
$py = $null
foreach ($v in @('3.12','3.11','3.10')) {
  $cand = (& py -$v -c "import sys;print(sys.executable)") 2>$null | Select-Object -First 1
  if ($cand -and $cand.Trim()) { $py = $cand.Trim(); break }
}
if (-not $py) {
  throw "需要 Python 3.10–3.12（rapidocr_onnxruntime 不支持 3.13+）。请安装后重试。"
}
```
并在装依赖前加一道版本护栏：`$major.$minor -le 3.12` 才继续。

### 1.2 `requirements.txt`（头部注释）
| 行 | 现状 | 改为 |
|---|---|---|
| 3 | `安装：py -m pip install -r requirements.txt` | `安装：先跑 scripts\setup_env.ps1（用 Python 3.10–3.12 建 .venv）；或 .venv\Scripts\python.exe -m pip install -r requirements.txt` |

并补一句：`rapidocr_onnxruntime` 要求 **Python ≤3.12**（本文件 `py` 默认若为 3.13 会装不上）。

## 6. DeepSeek LLM 模型名修复（实测新发现）

### 6.1 现象
后端 `/api/ask` 每次报 `llm 400: The supported API model names are deepseek-flash, deepseek-v4-pro, but you passed deepseek-v4.1-flash`，随后 `LLM failed, using extractive fallback` → DeepSeek LLM 形同虚设，永远走抽取式规则。

### 6.2 根因
`backend/app/config.py:124` 的 `llm_model` 兜底值是 `deepseek-v4.1-flash`；`.env` 里 `LLM_MODEL=` 留空，后端就用了这个无效名。（`cloud.py` 用的是 `.env` 的 `DEEPSEEK_MODEL=deepseek-chat`，所以 `cloud --llm`/`story` 正常，只有后端 LLM 路径坏。）

### 6.3 实测模型名有效性（真实调用）
| 模型名 | 结果 |
|---|---|
| `deepseek-chat` | ✅ 有效（`cloud.py` / `.env` 在用） |
| `deepseek-flash` | ✅ 有效（= 官方「V4.1 Flash」的真实 API 名） |
| `deepseek-v4-pro` | ✅ 有效（= 官方「V4 Pro」） |
| `deepseek-v4.1-flash` | ❌ 400 无效 |

### 6.4 改法（二选一，推荐 1）
| # | 文件 | 位置 | 改为 |
|---|---|---|---|
| 1 | `.env` | 第 113 行 `LLM_MODEL=` | `LLM_MODEL=deepseek-chat`（一行，已实测生效） |
| 2 | `backend/app/config.py` | 第 124 行 | 兜底值 `deepseek-v4.1-flash` → `deepseek-chat`（根治，防止别的机器漏配 `.env`） |

并同步 `docs/API_KEYS.md` 与项目说明书里的模型名口径：官方写的「V4.1 Flash」真实 API 名是 `deepseek-flash`（不是 `deepseek-v4.1-flash`）。

> 附带：LLM 模式下 `/api/ask` 的 `evidence` 为 0 条（生成式无引用），抽取式才有「页码+原文引用」。若赛题强调「回答引用可回溯」，需确认 LLM 回答也要挂 evidence。
