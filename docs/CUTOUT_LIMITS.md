# 边界优先切割：实测结论（2026-11-06）

你的判断是对的：**掩膜不该是矩形**。我把切件改成了“算子找边界 + agent 判断”，
下面是每一条路实测的结果，包括失败。

## 已实现（可被别的 agent 调用）

| verb | 输入 | 输出 |
|---|---|---|
| `agent probe` | 页面图 | 区域表：面积、框、主色、孔洞数、是否贴边、边缘强度 |
| `agent inspect` | 点/框 | SAM 提案 → 区域 id |
| `agent cut` | 区域 id spec | RGBA 切件（边界，非矩形） |
| `agent part` | 点提示 | 墨线封闭 cell 的切件 + 自动 pivot |
| `agent review` | 切件 json | 机器验收：连通性/纸色占比/pivot |

`review` **实测有效**：它拒绝了我之前手搓的矩形手臂切件——
`{"accept": false, "components": 2, "single": true, "paper_share": 0.236, "pivot_on_piece": false}`。
也就是说，“两块拼在一起 + pivot 不在件上”这种错误，机器能自己判出来。

| 页面 | 方法 | 结果 |
|---|---|---|
| p17 劳拉 | 矩形 | ✗ 带上脸颊和裙子 |

| p05 | 墨线 + 粗块保留（`keep_thick`） | △ 头发保住了，但木地板也被当成“粗黑块”并进来 |

## 结论（一句话）

**“算子找边界”只在轮廓闭合时成立；而儿童手绘本里，角色肢体被脸、道具、地面遮挡是常态。**
所以：
- 能切的页：平面背景、肢体与身体分离（p05 的浅色角色、p16 查理）；
- 切不出的页：肢体压在脸上（p17）、黑发/深色地面（p05 露塔）。

这不是调参能解决的，需要**补画轮廓**（人工或专门的线稿模型），我没有继续硬调。
