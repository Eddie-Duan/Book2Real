# p17 挥手为什么做不成，以及现在的做法

## 你的问题

> 为什么掩膜就一定是矩形？这样会把脸的一部分也给截取下来。
> 就不能用一些算子找边界，然后 agent 判断哪些是一体的、是什么？

**你说得对，矩形是错的。** 我把矩形改成了“算子找边界 + agent 判断”，但这一步之后我还是没成功——原因不是算子不够好，而是**这一页的手压在脸颊上，根本没有闭合的轮廓**。下面是逐条实测。

## 已经改成边界优先（代码已落地）

`python -m book2real agent` 新增：

| verb | 作用 |
|---|---|
| `probe` | 算子切分 → 区域表（面积、框、主色、孔洞数、是否贴边、边缘强度） |
| `inspect` | SAM 对某点/某框的提案，翻译成区域 id |
| `cut` | 按区域 id 集合 + 孔洞生成 RGBA 切件（边界，不是矩形） |
| `review` | 机器验收：连通性 / 纸色占比 / pivot 是否在件上 |
| `part` | 点提示 + **墨线封闭**的 cell，pivot 由几何自动推导（不手调） |

`book2real/cast/cells.py`：黑墨线当墙（`ink_mask` + `cells`），这样脸和手臂不会被颜色量化并到一起。
`book2real/cast/partkit.py`：点提示切件 + 自动 pivot。
`book2real/cast/segkit.py`：区域表、评分、spec 切件。
`book2real/cast/cutout.py`：负空间法（把周边大块画成墙，取剩下的连通域）。

## 这四种方法在 p17 上的实测结果

| 方法 | 结果 |
|---|---|
| 矩形切 | **失败**：带上了脸颊和裙子一角（你看到的） |
| 颜色区域（`probe`） | **失败**：手臂和脸同为肤色，量化后是同一个区域（id 50 覆盖了整张脸） |
| 墨线 cell（`cells`） | **失败**：手的轮廓压在脸颊上，墨线不闭合，cell 合并成整页（64% 面积） |
| 负空间（`cutout`） | **失败**：红纸没有边界，整页连成一片，取出来还是整页 |
| SAM 点提示 | 只能给出“人+纸”的联合区域，不是手臂 |

**根因**：这一页的构图里，手臂没有一条自己的闭合轮廓。它一边是纸，一边是脸。任何“沿着轮廓切”的算子都需要轮廓先存在。

## 试图补轮廓（也失败）

用 Recraft 在“手与脸颊之间”inpaint 一块纸色，好让手腕变成一条边：

- 掩膜：`(0.690, 0.615, 0.905, 0.700)`，约 6240 px
- 结果：**Recraft 在那里画了一只鸟**（`runs/agent/p17/hand_cmp.jpg`）
- 花费 $0.04，已放弃这条路线

这印证了上一轮的结论：Recraft 擅长“纹理/背景”，不适合“按指令补一小块语义明确的空白”。

## 现在的做法（不撒谎的版本）

`scripts/p17_breathe.py`：**不做切割**，对修好手腕的整页做小幅位移 + 缩放循环（±3px / 0.6%），渲染成 22 帧 GIF。

- 为什么不用旋转：没有闭合轮廓，旋转必然露缝；
- 为什么不用之前那个矩形挥手：它把脸颊带走了；
- 这个循环的幅度是**刻意压小**的，看起来是“纸页在呼吸”，不是“人在挥手”。

## 如果你想看到真正的挥手，有三条路

1. **换一页**：找一张手臂和身体分开画的页（p05、p07 这类站姿页），`agent part` 的墨线 cell 就能干净切开——这是现在就能做的；
2. **人工补画**：在手和脸颊之间手动画一条墨线（Krita/PS 两分钟），之后的算子链就能自动切开；
3. **接受“整页微动”**：这就是现在 p17 的效果。
